# Orion PM guide and Works preparation

The reader can learn a complete local task lifecycle, find one Works entry and
reach the independent product page. All source and previews remain private
until Dan reviews the whole package.

1. The complete guide is visible in initial HTML and after hydration, with its own
   canonical URL, Article metadata, responsive figure, sitemap entry and explicit
   Agent systems lens membership. It teaches the installed CLI rather than raw
   task-file edits. Executing its shell blocks proves one winner, one loser,
   evidence/completion, stale generation refusal and safe release of unfinished work.
2. Works contains exactly one PM card in Open Source, with MIT and the intended
   product and proposed source destinations, following existing ordering rules.
3. Product links use the existing independent-site model: normalize no-slash URLs,
   explicitly proxy the bare path, strip the Works prefix from asset requests,
   and avoid a physical hub route that would shadow the proxy.
4. Content separates task claims, native resource leases and permissions, states
   the observed local support row and artifact-specific browser proof, and avoids
   unsupported package-index/public-release/platform claims.

Test seams: existing guide compiler, Works/sitemap/route guards, complete installed
CLI walkthrough, built route HTML and a real browser through a local proxy.
A local proxy proves intended wiring, not an actual Vercel deployment. No remote
push, merge, deployment, syndication or account operation is part of preparation.
