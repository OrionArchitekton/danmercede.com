# Result-capture release surfaces

Status: privately prepared. Publication requires the reviewed release action set.

## Scenarios and acceptance

1. A Works visitor finds the MIT result-capture project in Open Source & Tooling,
   follows its own product page, and understands that snapshots bound one selected
   UTF-8 string while complete text remains recoverable by reference. Existing
   Works projects, featured essays and Thoughts remain unchanged.
2. A guide reader downloads the selected wheel and source archive, checks both
   exact release hashes, installs without runtime dependencies, and completes the
   synthetic capture, quota, inspection, backup/recovery and reinstall walkthrough.
   Commands share one selected working folder and shell. The guide describes the
   verified platform and visible uncertainty without implying action authority,
   token/memory bounds, native agent adapters or estate runtime adoption.
3. A visitor opening the Works path with or without its trailing slash receives
   the product site's HTML and prefix-stripped assets from its own external origin.
   The site owns its product canonical; the hub owns the guide's canonical, Article
   metadata, sitemap and navigation. The hub does not create a physical page that
   could shadow the proxy. Source assets and guide must be available before the
   public navigation is enabled.

Primary test seams: existing Works/guide bundle and routing checks, the built
guide HTML, and all guide command blocks executed against the exact local release
assets. A local routing rehearsal verifies the selected proxy rules and content
types; it does not prove Vercel deployment behavior. Public acceptance requires
later unauthenticated production navigation and deployment/source parity.

Constraints: no substrate changes, credentials, services, DNS, unrelated Works
routes, library behavior, starter pins or installed estate configuration changes.
